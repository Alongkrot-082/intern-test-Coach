## จุดที่สงสัย

- `GET /api/tasks` ใช้ `projectId` ใน query ได้อย่างปลอดภัยเมื่อ bind เป็น SQL parameter; ไม่ใช่ SQL injection ในรูปแบบเดิม
- การกรอง Task ของผู้ใช้ในหน้า Employee เป็นการกรองซ้ำเพื่อ UI เท่านั้น; การจำกัดข้อมูลจริงต้องทำที่ API ด้วย ซึ่ง route ในส่วนนี้ทำไว้
- Admin ย้อนสถานะ Done เป็น To Do ได้ตามโจทย์; ข้อห้ามเปลี่ยนกลับใช้กับ Employee เท่านั้น
